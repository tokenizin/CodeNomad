# Slice 8: A11y & Polish

**Complexity:** standard
**Slice:** polish
**Track:** implementation

## Summary

Add accessibility enhancements and polish to the notification system components (NotifyHistoryPanel, ChoiceBar). The feature is functionally complete but lacks:

1. `prefers-reduced-motion` CSS overrides (no animations/transitions when user prefers reduced motion)
2. An `aria-live` region that announces new notification arrivals to screen readers
3. Focus management (trap focus inside panel when open, restore focus on close)
4. A11y-specific unit tests for all of the above

## Acceptance Criteria

| AC | Description |
|----|-------------|
| AC-1 | `prefers-reduced-motion` media query disables all `transition` and `animation` on notify-related CSS classes |
| AC-2 | ARIA live region `role="status"` announces new notification count when events arrive |
| AC-3 | Focus is trapped inside NotifyHistoryPanel when open; restored to toggle button when closed |
| AC-4 | ChoiceBar receives focus on first option when it appears (auto-focus first button) |
| AC-5 | All new a11y tests pass (100%) |
| AC-6 | 0 regressions in existing notify tests |

## Approach

### 1. `prefers-reduced-motion` CSS

Add a media query block to the notify-history CSS that disables all `transition` and `animation` properties:

```css
@media (prefers-reduced-motion: reduce) {
  .notify-history-panel,
  .notify-history-panel *,
  .notify-history-backdrop,
  .choice-bar,
  .choice-bar * {
    animation: none !important;
    transition: none !important;
  }
}
```

This should go in the existing CSS files or a new notify-specific CSS file referenced by the panel component.

### 2. ARIA Live Region for Notifications

Add a `role="status"` `aria-live="polite"` region in the NotifyHistoryPanel that reads new notification count when unread events arrive. This can be done with a `createEffect` that watches `unreadCount()` and updates a hidden span visible only to screen readers.

**Pattern (sr-only):**
```tsx
<span class="sr-only" role="status" aria-live="polite">
  {/* Dynamic text generated by createEffect */}
</span>
```

The `sr-only` class already exists in the codebase — it visually hides content while keeping it accessible to screen readers.

### 3. Focus Management

**NotifyHistoryPanel:**
- On mount (`createEffect` on first render), call `focus()` on the panel container
- On ESC/close, restore focus to the toggle button that opened the panel (pass a `triggerRef?: HTMLButtonElement` prop or a `restoreFocusRef` callback pattern)
- Optionally add a focus trap: Tab cycling within the panel (first element → Tab → last element, last element → Tab → first element)

**ChoiceBar:**
- When `props.choice` becomes non-null, auto-focus the first choice button
- Use `createEffect` with `setTimeout` to ensure DOM is rendered before calling `.focus()`

### 4. Tests

Create a new test file (or add to existing):

- **`notify-history-a11y.test.tsx`** — SolidJS component tests using `node:test`:
  - Test that `sr-only` region renders with correct count
  - Test that `prefers-reduced-motion` is referenced (mock `window.matchMedia`)
  - Test that focus management behaviors exist (focus on mount, restore on close)
  - Test that ChoiceBar auto-focuses first option

## Implementation

### Step 1: Create `notify-history.css`

Create `packages/ui/src/styles/components/notify-history.css` with the reduced-motion override and any focus-related styles.

```css
/* Notify History Panel — Accessibility Styles */

@media (prefers-reduced-motion: reduce) {
  .notify-history-panel,
  .notify-history-panel *,
  .notify-history-backdrop,
  .choice-bar,
  .choice-bar * {
    animation: none !important;
    transition: none !important;
  }
}

/* Focus-visible ring for keyboard navigation */
.notify-history-item:focus-visible {
  outline: 2px solid var(--color-primary, #3b82f6);
  outline-offset: -2px;
}
```

### Step 2: Modify `notify-history-panel.tsx`

- Import the CSS file at top of component
- Add `restoreFocusRef` prop (optional `{ current?: HTMLElement }`)
- Add `panelRef` for focus management
- Add `createEffect` on mount to focus the panel container
- Add ESC handler that restores focus before calling `onClose`
- Add `sr-only` `role="status"` span that updates with unread count
- Add tab trap (optional but recommended)

### Step 3: Modify `instance-tabs.tsx`

- Create a ref for the notify toggle button
- Pass it as `restoreFocusRef` to NotifyHistoryPanel

### Step 4: Modify `choice-bar.tsx`

- Add auto-focus on first button when choice appears
- Use `createEffect` with `queueMicrotask` or `requestAnimationFrame` to focus after render

### Step 5: Create tests

Create `notify-history-a11y.test.tsx` with tests for:
1. Live region renders with correct aria attributes
2. Live region text updates when unread count changes
3. Focus management behaviors
4. ChoiceBar auto-focus

Run: `npx tsx --test packages/ui/src/components/notify-history-a11y.test.tsx`
